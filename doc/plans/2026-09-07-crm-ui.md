# CRM felület — vizuális újratervezés, kivitelezési terv

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A CRM extension négy képernyője a hoszt téma-tokenjeiből öltözzön, olvasható hierarchiával és formában is látszó állapottal, változatlan információs szerkezet és változatlan viselkedés mellett.

**Architecture:** Egyetlen `ui/style.css` nő 15 sorról ~350-re, kizárólag `crm-` prefixű osztályokkal és `var(--token, fallback)` alakú színekkel. A négy `.tsx` jelölése átépül; egyetlen rpc-hívás, argumentum, hibakezelés és állapot-átmenet sem változik. Az 1. feladat a közös alapot és egy CSS-szerződés tesztet rak le, a 2–5. feladat egy-egy képernyőt visz át rá, a 6. élő hoszton igazolja.

**Tech Stack:** Plain ESM + TSX, esbuild (`scripts/build.mjs`), `node --test`. Nincs új függőség, nincs CSS-keretrendszer, nincs jsdom.

**Spec:** `doc/specs/2026-09-07-crm-ui-design.md`
**Jóváhagyott látványterv:** `claude.ai/code/artifact/64cfad52-84bf-46e3-a8a8-1fe76196cf5d`

## Global Constraints

- Az extension **nem importálhat** a host `src/` fájából, és nem tölthet be betűtípust: a `--font-sans`, `--font-display`, `--font-mono` tokeneket olvassa.
- Minden CSS-osztály `crm-` prefixet visel. A hoszt a lapot a saját dokumentumába injektálja; egy prefix nélküli szabály a shellt is átstílusozná.
- Minden szín `var(--token, fallback)` alakú. A stíluslapon nyers hexa- vagy `rgb()`-érték csak `var()` fallback-pozícióban állhat.
- A `--status-*` tokencsaládot **nem használjuk** (spec 2.): jelentései (fut / hiba / tétlen) nem esnek egybe a CRM trigger-típusaival.
- A rangsorolás a szerveré: a lap sem a figyelem-listát, sem a javaslatokat nem rendezi újra.
- Soha nem `dangerouslySetInnerHTML`. Minden tárolt szöveget tartó doboz `overflow-wrap: anywhere`.
- A jelentést soha nem csak szín hordozza: minden csík mellett szöveges pill is áll.
- Nincs `any` a `.tsx`-ben. Operátor-felé menő szöveg és kommentek magyarul.
- Lint baseline 345, nem mozdul. Lint szabályt elnyomni vagy megkerülni tilos.
- **A meglévő tesztek szabálya (spec 5.):** ha egy UI-teszt elbukik, az alapfeltevés az, hogy a kód romlott el, nem a teszt. Átírni csak akkor szabad, ha a bukás oka bizonyítottan a jelölés alakja, és az átírt teszt ugyanazt a bekötést őrzi (ugyanaz a mutáció bukjon rá). Gyengíteni, hogy átmenjen, tilos.

```
/\.useEffect\)\(feladatokatTolt,\s*\[accountId\]\)/
/onClick:\s*\(\)\s*=>\s*elfogad\(s\.id\),\s*disabled:/
```

Az elsőt semmi nem érinti (a `useEffect` hívása nem jelölés). A másodikra a 2. feladat külön kitér.

```js
import assert from 'node:assert/strict'
import fs from 'node:fs'
import test from 'node:test'

/**
 * A stíluslap szerződése (spec 2. és 7.).
 *
 * A `scripts/build.mjs` a `ui/style.css`-t SIMA MÁSOLÁSSAL viszi
 * `dist/style.css`-be -- nincs feldolgozás --, ezért a forrást olvassuk,
 * buildelés nélkül. Ha a build egyszer feldolgozni kezdi, ezt a tesztet a
 * kimenetre kell átállítani, különben olyasmit igazol, ami nem kerül ki.
 */
const css = fs.readFileSync(new URL('../ui/style.css', import.meta.url), 'utf8')

/** A szabályok választói, at-szabály-preludiumok nélkül. */
function valasztok() {
  return [...css.matchAll(/(?:^|[};])\s*([^{};@]+?)\s*\{/g)]
    .map((m) => m[1].trim())
    .filter((s) => s.length > 0)
    .flatMap((s) => s.split(',').map((x) => x.trim()))
}

test('a stiluslap nem tolt be betutipust', () => {
  assert.equal(
    /@font-face|@import|fonts\.googleapis|fonts\.gstatic/.test(css), false,
    'a hoszt mar betoltotte a betuket; a --font-* tokeneket kell olvasni',
  )
})

test('minden valaszto crm- prefixet visel', () => {
  const rosszak = valasztok().filter((s) => !s.includes('.crm-'))
  assert.deepEqual(rosszak, [], 'prefix nelkuli szabaly a hoszt shelljet is atstilusozna')
})

test('minden szin tokenbol jon, fallbackkel', () => {
  // A var(--token, fallback) hivasokat kivagjuk; ami hexa marad, az nyers.
  const maradek = css.replace(/var\(\s*--[a-z0-9-]+\s*(?:,[^;]*?)?\)/g, 'VAR')
  const nyers = [...maradek.matchAll(/#[0-9a-fA-F]{3,8}\b/g)].map((m) => m[0])
  assert.deepEqual(nyers, [], 'nyers szin csak var() fallback-pozicioban allhat')
})

test('minden var() hivas visz fallbacket', () => {
  const fallbackNelkul = [...css.matchAll(/var\(\s*(--[a-z0-9-]+)\s*\)/g)].map((m) => m[1])
  assert.deepEqual(fallbackNelkul, [], 'egy atnevezett token nelkul a lap olvashatatlan lenne')
})
```

```tsx
/**
 * A figyelem-sor típusához tartozó osztályok.
 *
 * Tiszta függvény, mert ez az egyetlen hely, ahol a `rangsor` négy
 * trigger-típusa vizuális súlyt kap, és külön tesztelhetőnek kell lennie
 * attól, hogy a lap egyáltalán renderelődik-e. A sorrend szándékosan egyezik
 * a `src/attention.mjs` `SULY`-áéval: ha a kettő elcsúszik, az azt jelentené,
 * hogy a lap más súlyt mutat, mint amit a szerver rangsorolt.
 *
 * Ismeretlen típus nem tűnik el és nem dob: semleges osztályt kap, mert egy
 * új trigger bevezetése nem teheti láthatatlanná a saját sorát.
 */
export function figyelemOsztaly(kind: string): { sor: string; pill: string } {
  switch (kind) {
    case 'sajat_igeret': return { sor: 'crm-k-sajat', pill: 'crm-pill-sajat' }
    case 'valasz_nelkul': return { sor: 'crm-k-valasz', pill: 'crm-pill-valasz' }
    case 'nema_ugy': return { sor: 'crm-k-nema', pill: 'crm-pill-nema' }
    case 'idegen_igeret': return { sor: 'crm-k-idegen', pill: 'crm-pill-idegen' }
    default: return { sor: 'crm-k-idegen', pill: 'crm-pill-plain' }
  }
}
```
